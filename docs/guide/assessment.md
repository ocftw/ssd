# 透過「威脅建模」盤點組織風險

威脅建模是帶領受稽核組織成員透過一系列結構化活動，辨識對業務最關鍵的流程、關鍵資產與其面臨的威脅，並理解關鍵流程若遭中斷或暴露於惡意行為者的後果。惡意行為者經威脅剖析被界定後，組織可產出風險矩陣與威脅剖析報告，作為稽核員提出建議的基礎。讓組織自身的知識與經驗成為風險評估的核心，稽核員才能把威脅與建議寫進組織能認同的敘事中。成員在稽核結束後也較能主動延續對已識別威脅的處置。

## 基本步驟

1. **釐清關鍵流程與資產**：聚焦對組織運作不可或缺的流程與關鍵資產，描述其中斷或外洩時的影響。引導題組與紀錄方式見（[見參考文件](#reference)）。
2. **辨識威脅並剖析惡意行為者**：就各流程與資產盤點威脅來源，並透過威脅剖析掌握對手能力與意願等判斷輸入。
3. **評估並排序風險**：將威脅納入風險矩陣，依可能性與影響收斂優先處理順序。評分與欄位定義見（[見參考文件](#reference)）。
4. **產出威脅文件並連結後續行動**：彙整威脅象限與威脅剖析重點（例如：對手能力與意願、關鍵流程的攻擊影響排序、各類攻擊的可能性），作為稽核建議與改善討論的依據。

## 執行建議

- 先從工作流程與關鍵資料描繪威脅情境，再談具體控制措施與工具。先對齊組織如何運作，威脅建模的結論才接得上實務。
- 假設每個組織的威脅樣態都不同，並依倡議主題、合作對象與資料類型調整威脅剖析假設，矩陣與報告才足以支撐後續決策。
- 先收斂少數（例如：三至五項）最高優先風險再深入。項目過多時難以形成行動共識，也會稀釋後續資源投入。
- 讓組織成員主導描述流程與場景。稽核員協助結構化提問與記錄，較容易在稽核後延續主動應對。

## 注意事項

- 確保任何實體筆記、圖稿在數位記錄完成後立即擦除並銷毀。
- 確保此過程的任何數位記錄都受到安全保護和加密。
- 考量進行此過程的空間。確認誰可以進入或取得監視影像，以及若活動跨日或隔夜，該空間是否有門鎖或門禁管制。
